# Slate 0.1.12: final interaction polish

The final delivery is `releases/2026-10-03-final-polish`, containing Windows/Linux x64 applications and archives, a Debian installer, Android APK, independent web build, previews, instructions and checksums. Source remains `.`.

| Reported issue                                                                  | Final behavior                                                                                                                        | Reason                                                            |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Pinching loses its focal point and stutters                                     | Paper transforms once per frame under the moving midpoint; its canvas resizes after release; wheel zoom follows the pointer           | Users keep their place without repeated layout and buffer changes |
| Workspace chrome and Back change abruptly                                       | Chrome slides upward; note arrival and library return animate; Android exposes gesture progress and cancellation                      | Navigation preserves spatial continuity                           |
| Drawer swipes conflict with Android Back                                        | Swipe horizontally across note controls or use Document actions; persistent side handles are removed from notes and the library       | Both panels remain reachable while the page stays clear           |
| An open notebook cannot be renamed                                              | The existing title bar becomes an editable field, with Enter/blur to save and Escape to cancel                                        | Renaming preserves the layout, document ID, pages and ink         |
| Phone Markdown chrome and selection marks occupy too much space                 | The mode row is 44 pixels plus its divider; selected marks are 32 pixels inside 44-pixel targets; statistics float at the lower right | Controls stay comfortable within the compact row                  |
| Equation popup closes on the second on-screen key and leaves its keyboard stuck | Keyboard taps stay in the composer; the popup fits above the keyboard; inserting or dismissing removes the keyboard                   | Complete expressions can be entered and saved on touch screens    |

The design pass preserves Slate's fonts, cool neutrals, slate-blue controls and paper treatment. Surface modes are Operate and Read, with variance 4, motion 4 and density 6. Routine motion explains navigation and controls rather than delaying editing. Arrival takes 240 ms and departure 180 ms; reduced motion bypasses spatial navigation effects.

Notebook zoom stores a normalized paper point for the full pinch. Pointer events update the gesture's latest scale and position; one animation-frame callback transforms the existing paper without rerendering React or resizing the drawing buffer. The final layout and scroll position publish together after release. Preview movement observes the same bounds and centering as the committed layout. Scroll anchoring is disabled inside the paper viewport. Existing 50–500% bounds, pressure, vector rendering, palm rejection and double two-finger undo remain intact.

The rendering check samples 13 frames while pinching in and out. Canvas dimensions remain unchanged throughout the gesture, then update once on release. The final paper position differs from its preview by less than half a CSS pixel. Additional checks cover both zoom limits and cancellation. These results establish the avoided redraws and position continuity, not a physical-device frame-rate measurement.

The library stays mounted underneath the document during a Back preview. It remains inert and excluded from accessibility navigation until the return commits. Gesture cancellation restores the document transform and keeps the active note. Android uses the AndroidX Back start/progress/cancel/commit callbacks and explicitly enables predictive Back; the ordinary Capacitor Back handler is disabled to avoid competing callbacks. Earlier Android versions use the same animated committed return. See [Android's progress API](https://developer.android.com/guide/navigation/custom-back/support-animations-views).

Closing mobile drawers release their pointer interception while their exit animation finishes. Header swipes and the existing menu open either panel without persistent handles. Mobile toolbar selection and open-popover backgrounds use 32-pixel marks with a quiet border while retaining 44-pixel hit areas. Horizontally overflowing display equations also receive keyboard focus so the reading surface remains accessible.

MathLive attaches its virtual keyboard outside the dialog by default, as described in its [virtual keyboard guide](https://mathlive.io/mathfield/guides/virtual-keyboard/). The equation composer now treats keyboard and symbol-variant taps as part of editing, while ordinary outside taps still dismiss the popup. It measures keyboard height during its entrance animation to keep the popup and actions above it. Closing the composer removes its listeners and explicitly hides the global keyboard. Android Back dispatches Escape on the document so dialog handlers receive it; a cancelled Back gesture keeps the draft open.

TypeScript checking and lint for the equation changes pass, with three existing warnings across shared components and the application hook. All 45 unit tests pass. The complete production browser suite passes 64 workflows with no failures or retries; one optional private Flexcil fixture is skipped. Coverage includes moving pinch anchors, stationary-scale panning, stable pinch rendering, mouse zoom, both notebook title fields, retained ink across rename/reload, predictive preview/cancel/return, reduced motion, absence of side handles, header swipes, menu access, compact statistics and selection marks, light/dark accessibility, offline editing, backups, import, vault navigation and existing touch/stylus behavior. The five equation checks tap real on-screen keys on phone/tablet/desktop, save a complete expression offline, confirm reachable actions, dismiss and reopen the editor, and exercise Android Back callbacks in a simulated native browser context.

The packaged Windows and Linux applications pass launch, import, heading edits, immediate close/save, relaunch, on-screen equation input/insertion/keyboard cleanup, ink, 500% zoom, backup export, offline reload and failed-save protection in hidden windows and isolated temporary profiles. Linux runs through WSLg in its compact layout with the sandbox disabled only for the test invocation. All 346 web files match byte for byte in both desktop archives and the APK. Android compiles the native predictive Back callbacks and passes signature verification; versionCode is 13 and its certificate matches the previous 0.1.11 debug build. Platform runtime details and archive verification are recorded in the delivery folder's `VALIDATION.md`.

Physical Android gesture, stylus and keyboard behavior still need a device check. This APK uses the existing development certificate; a release-signed installation requires its preserved release key. Keep existing profiles and the web origin. Flexcil handwriting and synchronized audio remain undecoded; source preservation and the import limitations are unchanged.
